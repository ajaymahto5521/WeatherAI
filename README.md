# Weather Intelligence Assistant

An end-to-end AI system that answers weather questions in plain language using:
- A trained ML forecasting model (scikit-learn)
- A RAG pipeline over authoritative weather documents (PostgreSQL + pgvector)
- An LLM-based agent with tools (LangChain / LangGraph)
- A fine-tuned severity classifier (Hugging Face + LoRA)
- A FastAPI REST API

> **Status:** Under active development — see the checklist below.

---

## Architecture

```
User
  │
  ▼
FastAPI /ask
  │
  ▼
Agent / Orchestrator (LangGraph)
  │
  ├──► RAG Retriever ──► PostgreSQL + pgvector ──► Weather reference docs
  │
  ├──► Live Weather Tool ──► OpenWeatherMap API
  │
  ├──► Forecasting Model ──► trained scikit-learn model
  │
  └──► Severity Classifier ──► fine-tuned DistilBERT (LoRA)
  │
  ▼
LLM (OpenAI / GPT-4o)
  │
  ▼
Structured JSON response { answer, sources, tools_used, model_prediction }
```

## Setup

### 1. Clone the repository

```bash
git clone <repo-url>
cd weather-intelligence-assistant
```

### 2. Create a virtual environment

```bash
python -m venv venv

# Windows
venv\Scripts\activate

# macOS/Linux
source venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Configure environment variables

```bash
cp .env.example .env
# Edit .env and fill in your API keys and database credentials
```

Required variables:
| Variable | Where to get it |
|---|---|
| `OPENAI_API_KEY` | https://platform.openai.com/api-keys |
| `OPENAI_MODEL_NAME` | Optional, defaults to `gpt-4o` |
| `OPENWEATHER_API_KEY` | https://openweathermap.org/api |
| `POSTGRES_*` | See Database Setup below |

### 5. Database Setup

```bash
# Start PostgreSQL with pgvector via Docker
docker compose up -d postgres

# Or connect to an existing PostgreSQL instance
# and run: CREATE EXTENSION IF NOT EXISTS vector;
```

## Training

### Forecasting model

```bash
python training/train_forecaster.py
```

Output: `models/forecaster.joblib` + evaluation metrics printed to stdout.

### Severity classifier

```bash
python training/train_severity.py
```

Output: `models/severity_classifier/` + a comparison of untrained, keyword and LoRA results.

The benchmark is `training/severity_data_realistic.py`: noisy site alerts (mixed units, distractor
numbers, misleading hype words, typos, held-out wording) whose labels follow the SOP thresholds in
`data/reference/`. A small slice of plain-language text is added to training.

Zero-shot LLM baselines on the same test set (needs `OPENAI_API_KEY`; results are added to
`models/severity_classifier/training_meta.json`):

```bash
python training/eval_zero_shot.py gpt-4o gpt-4o-mini
```

| Method (400 test alerts) | Accuracy |
|---|---|
| Untrained DistilBERT | 25.0% |
| Keyword rules | 29.0% |
| Zero-shot GPT-4o / GPT-4o-mini (labels only) | 48.0% / 48.5% |
| GPT-4o / GPT-4o-mini given the SOP thresholds | 87.0% / 78.8% |
| **LoRA fine-tuned** | **92.2%** |

On the older, cleaner synthetic text a zero-shot LLM scores higher than the fine-tuned model,
so the harder benchmark is what shows the value of fine-tuning on domain labels. The data is
generated; treat the numbers as a method comparison, not real-world accuracy.

## RAG Ingestion

```bash
python scripts/ingest_documents.py
```

This reads supported `.txt`, `.md`, and text-based `.pdf` files recursively from `data/reference/`, chunks the documents, generates embeddings, and stores them in PostgreSQL + pgvector. Scanned PDFs require OCR before ingestion. Files under `_optional/`, `_out_of_scope/`, and `_unprocessed/` are excluded.

### Ask questions from the terminal

Run the interactive terminal client from the project folder. Choose one of the five numbered questions or type your own question. It prints each answer without source or JSON details; enter `stop` to exit.

```powershell
.\venv\Scripts\python.exe scripts\ask.py
```

## Docker

Prerequisite: a `.env` with `POSTGRES_PASSWORD` (and the OpenAI/OpenWeather keys). The trained
models in `./models` (about 4 MB) are committed and copied into the image, so a clean clone needs
no training step. The RAG index is rebuilt into Postgres on every container start.

```bash
# Build and start everything (app + postgres)
docker compose up --build

# Stop everything
docker compose down
```

## Limitations

- The severity classifier is trained on a small synthetic dataset. Do not use it for real operational weather decisions.
- The forecasting model is trained on a sample/educational dataset. Accuracy depends on data quality.
- RAG quality depends on the documents ingested. The system will say so when context is insufficient.
